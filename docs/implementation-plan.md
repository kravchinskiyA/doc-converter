# План реализации проекта doc-converter

**Основание:** [technical-specification-final.md](./technical-specification-final.md) (версия 1.36), [architecture.md](./architecture.md), [design.md](./design.md).  
**Принцип формирования:** Строгая последовательность. Сначала реализуются все пользовательские интерфейсы (Frontend), затем проектируется схема данных и хранилище (БД), после чего реализуется серверная бизнес-логика, очереди и конвейеры обработки (Backend).

---

## ЭТАП 1. FRONTEND (Интерфейс, страницы и клиентская логика)

> **Стек:** Next.js 15 (App Router, FSD-архитектура), React 19, Tailwind CSS, shadcn/ui (дизайн-система Augen Pro, zero-shadows), `next-intl` (i18n), React Hook Form + Zod.

### 1.1. Базовая дизайн-система и UI-компоненты (Augen Pro)
- [x] Настройка палитры токенов (`#0f1012`, `#f2f2f4`, `#fdfdfd`, акцентный `#0071e3`), отказ от теней (`zero-shadows`) и настройка типографики (начертание 350).
- [x] Разработка базовых атомарных компонентов в `apps/web/src/shared/ui/`:
  - Кнопки: `Floating CTA Pill` (скругление 26px);
  - Контентные карточки: `Rounded Card` (скругление 54px, hairline-рамка 0.5px);
  - Бейджи и теги: `Pill Tag Chip` (скругление 9999px);
  - Инпуты, чекбоксы, модальные диалоги, шторки (Sheet), тосты уведомлений.
- [x] Глобальный лейаут: плавающее верхнее меню (`Floating Pill Navbar` 10px) и темный подвал (`Dark Band Footer` `#0f1012`).

### 1.2. Интернационализация (i18n)
- [x] Интеграция `next-intl` на базе App Router (`[locale]`: `uk` по умолчанию, `ru`, `en`).
- [x] Создание словарей переводов для навигации, форм, валидации Zod и системных сообщений.

### 1.3. Главная страница (`/[locale]/page.tsx`)
- [x] Блок Drag-and-Drop «Документы» (карточка 54px) для быстрой загрузки PDF и DOCX + кнопка диалога выбора файлов.
- [x] Интерактивный список добавленных файлов (изменение порядка, удаление, индикатор ограничений размера).
- [x] Индикатор доступных гостевых попыток (3 попытки) и кнопка запуска конвертации.
- [x] Информационные блоки: безопасность и обработка в ЕС, точность OCR (CER ≤ 2%), автоудаление через 12 часов.

### 1.4. Страницы направлений конвертации (`/[locale]/convert/[direction]/`)
- [x] `pdf-to-docx`: форма с интерактивной сеткой миниатюр страниц PDF и чекбоксами выбора страниц для OCR.
- [x] `docx-to-pdf`: форма загрузки DOCX-файлов (с проверкой лимита распаковки).
- [x] `images-to-pdf`: загрузка JPG/PNG/WEBP, drag-and-drop перетаскивание порядка файлов, тумблер «Объединить в один PDF» (формат A4, поля 10 мм).
- [x] `pdf-to-images` (`pdf-to-jpg`, `pdf-to-webp`): выбор страниц, селекторы DPI (72/150/300) и качества (1–100).

### 1.5. Страница ожидания и результатов (`/[locale]/results/[jobId]/`)
- [x] Карточка статуса задания: состояние по каждому файлу (в очереди, обработка, готов, отказ с понятной причиной без PII).
- [x] Список готовых файлов: имя, размер, кнопка скачивания и таймер обратного отсчета доступности (12 часов для гостя).
- [x] Кнопка генерации/скачивания единого ZIP-архива.
- [x] Кнопка перехода к новой конвертации.

### 1.6. Экраны аутентификации и восстановления (`/[locale]/auth/`)
- [x] `login` и `register`: формы ввода email и пароля (8–128 символов) с валидацией Zod.
- [x] `verify-email`: экран ввода 6-значного кода из письма (таймер 10 мин, макс. 5 попыток, кулдаун повтора 60 сек).
- [x] `forgot-password` и `reset-password`: запрос сброса пароля и установка нового пароля.
- [x] `recovery-code`: форма восстановления доступа через одноразовый резервный код при потере доступа к email.

### 1.7. Личный кабинет пользователя (`/[locale]/account/`)
- [x] **Профиль:** редактирование имени/фамилии, двухэтапная смена email (2 кода за 20 минут), смена пароля.
- [x] **Хранилище:** круговая/линейная шкала занятого объема, предупреждение при 75%, блокировка при 100%, кнопка полной очистки.
- [x] **Сохраненные файлы:** таблица результатов (сайт и API) с индивидуальным и массовым скачиванием/удалением.
- [x] **API-ключ:** создание ключа, скрытый просмотр (`••••••••`), копирование, перевыпуск через email-код.
- [x] **Тариф и подписка:** текущий статус, тумблер автопродления, кнопки смены тарифа и отмены подписки (с расчетом возврата).
- [x] **Резервные коды:** модальное окно однократного выпуска 10 резервных кодов восстановления.
- [x] **Служебный доступ:** интерфейс подтверждения/отзыва запросов техподдержки на просмотр сбойных файлов.
- [x] **Удаление аккаунта:** зона с предупреждением и подтверждением через 6-значный email-код.

### 1.8. Страница тарифов и шлюз оплаты (`/[locale]/pricing/`)
- [x] Переключатель периода «Месяц / Год» со скидкой 15%.
- [x] Карточки тарифов (Базовый 0 €, Pro, Максимальный, Enterprise) и сводная таблица лимитов.
- [x] Интеграция модального экрана оплаты Stripe Checkout (только для подтвержденных email).

### 1.9. Закрытая административная панель (`/[locale]/admin/`)
- [ ] Экран входа для персонала с обязательным вводом TOTP (2FA Authenticator).
- [ ] Дашборд метрик сервиса (очереди BullMQ, S3, статус ClamAV).
- [ ] Таблицы пользователей, квот и заданий конвертации (без доступа к содержимому документов).
- [ ] Журнал платежей Stripe и подписок.
- [ ] Панель экстренных действий: глобальная приостановка приема конвертаций, отзыв API-ключей.

### 1.10. Служебные страницы
- [x] Документация API (`/api-docs`), Условия сервиса (`/terms`), Политика конфиденциальности GDPR (`/privacy`), экраны `404` и `500`.

## ЭТАП 2. БАЗА ДАННЫХ И ОБЪЕКТНОЕ ХРАНИЛИЩЕ

> **Стек:** PostgreSQL, Prisma ORM, Amazon S3 (ЕС) + SSE-KMS, Redis.

### 2.1. Схема данных Prisma (`prisma/schema.prisma`)
- [ ] Модели пользователей (`User`), сессий (`Session`), аккаунтов (`Account`) под Better Auth.
- [ ] Модели кодов подтверждения (`VerificationCode`) и резервных кодов (`RecoveryCode` с хэшами scrypt).
- [ ] Модели тарифов (`Plan`), квот (`QuotaUsage`), подписок (`Subscription`), транзакций Stripe (`PaymentTransaction`).
- [ ] Модели заданий (`Job`), файлов (`InputFile`, `OutputFile`) с полями TTL, статусов и путей S3.
- [ ] Модель `TransactionalOutbox` для гарантированной передачи сообщений в очередь BullMQ.
- [ ] Модели служебных ролей персонала (`StaffRole`), TOTP-секретов и журнала доступов (`StaffFileAccessGrant`).
- [ ] Проектирование составных и частичных индексов по стандартам `postgres-patterns`.

### 2.2. Миграции и начальное наполнение (Seeding)
- [ ] Создание первой миграции `prisma migrate dev`.
- [ ] Скрипт `prisma/seed.ts` для фиксации базовых тарифных планов (Базовый, Pro, Максимальный).

### 2.3. Интеграция Amazon S3 (ЕС)
- [ ] Настройка клиента S3 SDK v3 в `packages/infrastructure/src/storage/` с шифрованием SSE-KMS.
- [ ] Конфигурация изолированных префиксов бакета: временные входящие файлы (`temp/`), постоянные результаты (`results/`).
- [ ] Политика жизненного цикла (Lifecycle Rules): автоудаление гостевых файлов через 12 часов.

## ЭТАП 3. BACKEND, ОЧЕРЕДИ И КОНВЕРТЕРЫ

> **Стек:** NestJS 10, Express, Better Auth, BullMQ, Redis, ClamAV, Sharp, pdf-lib, PDFium, LibreOffice, PaddleOCR, Stripe SDK, SESv2.

### 3.1. Общие контракты API (`packages/contracts`)
- [ ] Описание всех Zod-схем входящих DTO, ответов API и кодов ошибок без утечки внутренних данных.

### 3.2. Аутентификация, профили и безопасность (`apps/api/src/modules/auth`)
- [ ] Настройка Better Auth с адаптером Prisma.
- [ ] Сервис одноразовых почтовых кодов: генерация 6 цифр, проверка срока (10 мин), счетчик попыток (до 5), кулдаун (60 сек).
- [ ] Отправка почтовых кодов через Amazon SESv2 в ЕС (`@aws-sdk/client-sesv2`).
- [ ] Двухэтапная смена email (2 кода за 20 минут), смена пароля с отзывом сессий и API-ключей.
- [ ] Выпуск и проверка 10 одноразовых резервных кодов восстановления (scrypt).
- [ ] TOTP 2FA для административной панели.

### 3.3. Квоты, тарифы и биллинг (`apps/api/src/modules/billing`)
- [ ] Сервис раздельного учета квот документов и изображений.
- [ ] Атомарное резервирование квоты перед стартом задачи и освобождение при сбое.
- [ ] Таймеры восстановления попыток (5 часов для Базового, 2 часа для Pro).
- [ ] Интеграция Stripe: создание Checkout-сессий, обработка вебхуков с `raw body`, автоматический расчет возврата за неиспользованные дни при отмене подписки.

### 3.4. Потоковый шлюз файлов и антивирус (`apps/api/src/modules/files`)
- [ ] Потоковая загрузка файлов напрямую в S3 без накопления в оперативной памяти сервера.
- [ ] Обязательное антивирусное сканирование через ClamAV (stream/clamd) **до** допуска файла к обработке.
- [ ] Потоковая сборка и отдача ZIP-архивов через Archiver.

### 3.5. Очереди задач и воркеры (`apps/worker`, `apps/maintenance`)
- [ ] Модуль Transactional Outbox: публикация событий из БД в очередь BullMQ (Redis).
- [ ] Лимиты параллельности задач (Global Concurrency 5) и квот тарифов.
- [ ] Запрет автоматических повторов (retries) при сбое воркера для предотвращения бесконечных циклов.
- [ ] Фоновый сервис Maintenance: очистка устаревших файлов по TTL, проверка зависших задач, освобождение зарезервированных квот.

### 3.6. Движки конвертации и OCR (`packages/infrastructure/src/converters`)
- [ ] `Sharp + pdf-lib`: конвертация изображений в PDF (A4, поля 10 мм, центрирование, объединение).
- [ ] `PDFium + Sharp`: рендеринг PDF в миниатюры и изображения (72/150/300 DPI, качество 1–100).
- [ ] `LibreOffice (headless)`: конвертация DOCX в PDF с контролем лимитов распаковки (до 500 МБ).
- [ ] `PaddleOCR / PP-StructureV3`: распознавание PDF в DOCX (сохранение структуры, таблиц, CER ≤ 2%).
- [ ] Изоляция процессов конвертации: таймаут 10 минут, лимит памяти 2 ГБ на задачу.

### 3.7. Публичный REST API и администрирование (`apps/api`)
- [ ] Авторизация по `X-API-Key` в заголовке, валидация прав владельца.
- [ ] Выдача `202 Accepted` с идентификатором задачи и опрос статуса через интервал не чаще 5 сек.
- [ ] Rate limiting (10 созд/мин, 120 статус/мин, 10 скач/мин).
- [ ] Административные эндпоинты управления сервисом (экстренная приостановка, отзыв ключей).

## Контрольная приёмка и валидация
- [ ] Сквозные тесты (E2E) через контрольный набор документов (6 языков, сканы с CER ≤ 2%).
- [ ] Нагрузочное тестирование лимитов параллельности и памяти.
- [ ] Аудит безопасности по чеклисту `security-review` (отсутствие PII в логах, изоляция файлов в ЕС).
