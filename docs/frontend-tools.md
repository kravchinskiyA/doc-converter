# Компоненты, формы и переводы

**Дата:** 28 октября 2026 г.  
**Статус:** shadcn/ui + Tailwind CSS, React Hook Form + Zod и next-intl утверждены пользователем; библиотеки не установлены. Оформление сайта, кабинета и административной панели описывается отдельно в [design.md](./design.md).

## 1. Утверждённый набор

| Задача | Выбранное средство | Применение |
| --- | --- | --- |
| Компоненты интерфейса | shadcn/ui | Кнопки, поля, диалоги, меню, таблицы, вкладки, уведомления и состояния загрузки. Компоненты добавляются как редактируемый код проекта; готовая тема не считается выбранным дизайном |
| Стили компонентов | Tailwind CSS | Реализация отступов, размеров, адаптивности и будущих визуальных правил design.md. Цвета, шрифты, темы и композиция страниц этим не назначаются |
| Формы | React Hook Form | Состояние полей, ошибки, отправка и взаимодействие с сервером для входа, кодов, профиля, настроек и служебных форм |
| Схемы проверки данных | Zod + @hookform/resolvers | Проверка структуры и допустимых значений полей, подключение схем к формам. Серверная проверка NestJS остаётся обязательной |
| Переводы | next-intl | Тексты, формы числительных, даты и числа в Next.js App Router; украинский по умолчанию, русский и английский по ТЗ |

Источники: [shadcn/ui](https://ui.shadcn.com/docs), [официальная интеграция React Hook Form и Zod](https://ui.shadcn.com/docs/forms/react-hook-form), [next-intl для App Router](https://next-intl.dev/docs/getting-started/app-router). Совместимые версии и набор базовых компонентов закрепляются при реализации, а не копируются без проверки из примеров документации.

## 2. Границы применения

- Один набор базовых компонентов для сайта, кабинета и административной панели. Их визуальные различия задаются в design.md. Доступность клавиатурой, подписи полей, фокус и сообщения ошибок проверяются на готовых страницах; библиотека сама по себе не подтверждает качество интерфейса.
- React Hook Form управляет формой, Better Auth/NestJS — входом и правами. Клиентская форма не выдаёт квоты, не определяет тариф и не подтверждает платёж. Ограничения кодов и паролей сохраняются по ТЗ и [auth-design.md](./auth-design.md).
- Общие чистые схемы Zod можно использовать для контрактов клиент/сервер, но проверка в браузере не заменяет проверку запроса NestJS. Prisma-модели БД и секретные поля не передаются в клиентский пакет. Способ подключения Zod к NestJS ещё нужно закрепить.
- Поле выбора файлов и параметры конвертации могут быть частью формы; потоковая загрузка, фактический размер и безопасность содержимого проверяются отдельным конвейером NestJS. HTTP-платформа NestJS — утверждённый Express; приём потока остаётся задачей серверного конвейера.
- Для переводов используются идентификаторы локалей `uk`, `ru`, `en`. Зона домена `.ua` не является идентификатором языка. Префиксы языков в URL и сохранение выбранного языка пока не назначены.
- NestJS возвращает стабильные коды ошибок и параметры; интерфейс переводит их через next-intl. Текст исключения сервера не становится пользовательским сообщением. Денежные расчёты и сроки хранения остаются серверными; локальное форматирование их не изменяет.
- next-intl применяется в Next.js; выбор этой библиотеки не означает автоматического подключения переводов писем в NestJS. Шаблоны почты и их язык остаются отдельной реализацией.
