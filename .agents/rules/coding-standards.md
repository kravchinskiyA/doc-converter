# 8. Стандарты написания кода и разработки (coding-standards.md)

## Основные принципы

1. **Строгая типизация TypeScript:**
   - Категорический запрет на использование типа `any`.
   - Для неизвестных входящих структур использовать `unknown` с обязательным сужением типов через Zod.
   - Все контракты API, DTO и структуры настроек должны быть описаны в `packages/contracts` и валидироваться схемами Zod.
2. **Точечные правки и сохранение стиля:**
   - Вносить только минимально необходимые изменения, не переписывая соседние рабочие блоки.
   - Сохранять существующие комментарии, JSDoc/TSDoc и соглашения об именовании в репозитории.
3. **Безопасность логов:**
   - Запрещено логировать персональные данные (PII): email, полные имена, пароли, платежные реквизиты, сессионные токены, API-ключи, содержимое файлов.
   - Все системные логи должны содержать `requestId` и технический контекст операции.
4. **Актуальная документация через MCP:**
   - Перед написанием кода или конфигураций для сторонних библиотек (NestJS, Next.js, Prisma, BullMQ, Better Auth, Stripe, Tailwind CSS) обязательно использовать MCP-инструмент `context7` для проверки актуального синтаксиса и сигнатур методов.
5. **Тестирование:**
   - Любой новый функционал в `packages/core` и `apps/api` должен сопровождаться модульными и интеграционными тестами.
   - Внешние интеграции (AWS KMS, S3, SES, Stripe, ClamAV) в тестах должны быть изолированы и замокированы.
