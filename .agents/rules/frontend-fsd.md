# 3. Стандарты Frontend и Feature-Sliced Design (frontend-fsd.md)

## Стек Frontend (`apps/web`)
- **Фреймворк:** Next.js (React 19+, App Router).
- **Архитектурная методология:** Feature-Sliced Design (FSD) в директории `apps/web/src/`.
- **Стилизация и компоненты:** Tailwind CSS + shadcn/ui.
- **Управление формами и валидация:** React Hook Form + Zod (`@hookform/resolvers`).
- **Интернационализация:** `next-intl`. Основной язык — украинский (`uk`), также поддерживаются русский (`ru`) и английский (`en`).

## Структура слоев FSD (`apps/web/src/`)
1. `_app/`: Провайдеры контекста, глобальные стили, инициализация i18n.
2. `_pages/`: Композиция страниц для маршрутов App Router (`app/[locale]/...`).
3. `features/`: Пользовательские интерактивные сценарии (конвертация, загрузка, оплата, смена пароля).
4. `entities/`: Бизнес-сущности (пользователь, файл, задача конвертации, тариф, подписка).
5. `shared/`: Переиспользуемый код без привязки к бизнес-логике:
   - `shared/ui/`: UI-компоненты (shadcn/ui), примитивы.
   - `shared/api/`: Типизированный клиент API NestJS.
   - `shared/i18n/`: Локали и утилиты переводов.
   - `shared/lib/`: Общие утилиты и хелперы.

## Правила зависимостей FSD
- **Импорты строго сверху вниз:** `_pages` -> `features` -> `entities` -> `shared`.
- **Запрет горизонтальных импортов:** Модуль слоя `features` не может импортировать соседний модуль из `features`. То же правило действует для `entities`.
- **Public API:** Доступ к содержимому любого слайса/сегмента разрешен только через его публичный входной файл `index.ts`. Прямые импорты во внутренние файлы слайса запрещены.
- **Интерфейс и валидация:** Любые пользовательские формы валидируются через Zod-схемы, согласованные с `packages/contracts`.
