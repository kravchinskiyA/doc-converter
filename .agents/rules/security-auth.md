# 7. Безопасность, секреты и авторизация (security-auth.md)

## Стек безопасности и авторизации
- **Управление ключами:** AWS KMS в регионе ЕС.
- **Управление секретами:** AWS Secrets Manager в регионе ЕС.
- **Шифрование S3:** SSE-KMS с собственным ключом управления KMS.
- **Фреймворк авторизации:** Better Auth (интегрирован в NestJS) + адаптер Prisma.

## Политика разделения и защиты данных
1. **Хранение секретов:**
   - Пароли: необратимое хеширование с солью алгоритмом `scrypt` (Better Auth).
   - API-ключи пользователей: обратимое шифрование в PostgreSQL алгоритмом AES-256-GCM через `node:crypto` с защитой ключа данных в AWS KMS.
   - Секреты TOTP: шифрование через серверный мастер-секрет в Secrets Manager.
   - Почтовые OTP-коды: 6 цифр, время жизни 600 секунд, максимум 5 попыток, проверка через HMAC с серверным секретом.
2. **Сессии и сроки жизни:**
   - **Пользователи:** завершение после 7 суток бездействия, абсолютный максимум — 30 суток с момента входа.
   - **Администраторы и сотрудники поддержки:** завершение после 15 минут бездействия, абсолютный максимум — 8 часов, обязательный фактор TOTP.
   - **Серверная валидация:** Проверка сессии при каждом защищенном запросе через PostgreSQL. Кеширование сессий в cookie (`cookieCache`) отключено.
3. **Безопасность сессий и cookie:**
   - Cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, область хоста без `Domain`.
   - Защита от CSRF для всех изменяющих HTTP-запросов.
   - Фоновые опросы статуса задач не продлевают срок активности сессии.
4. **Изоляция и удаление аккаунтов:**
   - При удалении аккаунта все активные задачи в очереди немедленно снимаются, обработка прерывается, файлы удаляются, а результаты не публикуются.
   - Возврат неизрасходованных средств при добровольном удалении аккаунта не производится (по ТЗ).
