# 4. Backend и REST API (backend-api.md)

## Стек Backend (`apps/api`)
- **Платформа:** NestJS + Express (TypeScript).
- **База данных:** PostgreSQL через Prisma ORM (миграции и транзакции).
- **Авторизация:** Better Auth с адаптером Prisma; сессии в PostgreSQL без кеша в cookie (`session.cookieCache` отключен).
- **Платежи:** Stripe (подписки, разовые платежи, вебхуки со строгой проверкой сырого тела запроса `raw body`).
- **Транзакционная почта:** Amazon SES (v2) в регионе ЕС через `@aws-sdk/client-sesv2`.

## Архитектура API и обработка запросов
1. **Асинхронная модель приема задач:**
   - При успешном приеме запроса на конвертацию API возвращает `202 Accepted` с `jobId`.
   - Клиент опрашивает статус через `GET /api/jobs/:id` (лимит: не чаще 1 раза в 5 секунд на задание, до 120 запросов/мин на аккаунт).
   - Redis и BullMQ клиенту напрямую не доступны.
2. **Потоковая передача файлов:**
   - Загрузка и скачивание файлов производятся потоками (Streams) без буферизации всего файла в оперативной памяти.
   - Скачивание ZIP-архива использует потоковую упаковку через `Archiver` на лету из готовых результатов.
3. **Безопасность и обработка ошибок:**
   - Каждый входящий HTTP-запрос получает уникальный `requestId`.
   - В логах строго запрещено выводить персональные данные (PII), пароли, токены сессий, API-ключи и содержимое файлов.
   - Формат ошибок: стандартизированный JSON с машинным кодом, понятным сообщением и `requestId`.
4. **Контроль квот и тарифов:**
   - Резервирование квоты происходит ДО постановки задачи в очередь в единой транзакции БД.
   - Списание квоты производится только после гарантированного успешного завершения конвертации и фиксации результатов в S3.
