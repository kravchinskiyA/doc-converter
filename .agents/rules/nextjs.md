# Стандарты разработки Next.js (nextjs.md)

Данный документ регламентирует лучшие практики разработки клиентской и серверной части в приложении `apps/web` на базе фреймворка Next.js (App Router, React 19+).

---

## 1. Организация кода и взаимодействие с FSD

В монорепозитории архитектура `apps/web` подчиняется методологии **Feature-Sliced Design (FSD)**, зафиксированной в [.agents/rules/frontend-fsd.md](frontend-fsd.md):
- Директория `app/[locale]/...` используется **исключительно как тонкий маршрутизатор**: определение роутов, корневых лейаутов, файлов `page.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx` и передача управления в слой `_pages/` или `features/`.
- Компоненты, хуки, типы и состояние группируются по FSD-слоям (`_pages/`, `features/`, `entities/`, `shared/`), а не размазываются по директориям Next.js.
- Переиспользуемые утилиты размещаются в `shared/lib/`, клиентские API-клиенты — в `shared/api/`, базовые UI-примитивы — в `shared/ui/`.

---

## 2. Архитектура компонентов: Server Components First

По умолчанию все компоненты в App Router являются **React Server Components (RSC)**.

### Принципы:
1. **Server Components по умолчанию:** Все компоненты страниц, лейаутов и контейнеров данных должны быть серверными. Это исключает передачу лишнего JS-кода клиенту, ускоряет первую загрузку (FCP/LCP) и обеспечивает безопасность (отсутствие утечки секретов и приватных API).
2. **Граница `'use client'` как можно ниже в дереве:** Директива `'use client'` должна объявляться только в конкретных листовых интерактивных компонентах (кнопки с обработчиками, поля ввода, модальные окна, компоненты с локальным стейтом `useState`/`useEffect`).
3. **Запрет массового `'use client'`:** Запрещено помечать директивой `'use client'` целые страницы, лейауты или крупные композиционные секции, если интерактивна лишь малая часть.

```tsx
// ✅ ХОРОШО: Серверная страница передает пропсы в компактный клиентский компонент
// apps/web/src/_pages/converter/ui/ConverterPage.tsx (Server Component)
import { ConverterWidget } from '@/features/convert-file'; // Client Component внутри

export default async function ConverterPage() {
  return (
    <main>
      <h1>Конвертация файлов</h1>
      <ConverterWidget />
    </main>
  );
}
```

```tsx
// ❌ ПЛОХО: Вся страница помечена как клиентская ради одного обработчика
'use client';
export default function ConverterPage() { ... }
```

## 3. Загрузка данных и потоковая передача (Streaming)

1. **Серверный Fetch:** Загрузка данных выполняется напрямую в Server Components с использованием нативного `fetch` или типизированных серверных клиентов. Запросы автоматически дедуплицируются Next.js.
2. **Параллельная загрузка:** Независимые данные запрашиваются параллельно через `Promise.all()`, чтобы избежать каскадных задержек (waterfalls).
3. **Streaming & Suspense:** Долгие операции и динамические блоки оборачиваются в `<Suspense fallback={<Skeleton />}>` для мгновенной отдачи каркаса страницы.
4. **Файлы состояний роута:**
   - `loading.tsx`: Мгновенный скелетон при переходе на роут.
   - `error.tsx`: Изолированный перехват ошибок сегмента (обязан быть `'use client'`).
   - `not-found.tsx`: Стилизованная страница отсутствия ресурса (вызывается через `notFound()`).

## 4. Производительность и Core Web Vitals

1. **Оптимизация изображений (`next/image`):**
   - **Запрещен** нативный тег `<img>`.
   - Использовать только компонент `Image` из `next/link` / `next/image` с обязательными атрибутами `alt`, `width`, `height` (или `fill`) и `priority` для LCP-элементов первого экрана.
2. **Оптимизация шрифтов (`next/font`):**
   - Все шрифты загружаются через `next/font/google` или `next/font/local` с автоматическим self-hosting и нулевым layout shift (CLS).
3. **Динамический импорт (`next/dynamic`):**
   - Тяжелые интерактивные библиотеки (редакторы, графики, модалки) импортируются динамически с опцией `ssr: false`, если они не нужны для первичного рендера.

---

## 5. Навигация и роутинг

1. **Внутренние ссылки:** Категорически запрещено использовать `<a>` для внутренней навигации. Использовать `<Link>` из `next/link` (или локализованный роутер `next-intl`).
2. **Клиентская навигация:** Использовать хуки `useRouter`, `usePathname`, `useSearchParams` исключительно из `next/navigation` (использование устаревшего `next/router` запрещено).

---

## 6. Управление состоянием

1. Предпочитать локальное состояние (`useState`, `useReducer`) на уровне листовых интерактивных компонентов.
2. Для разделяемого клиентского состояния использовать легковесные хранилища (Zustand) в рамках соответствующего FSD-слайса (`features/*` или `entities/*`).
3. Синхронизацию фильтров и пагинации реализовывать через URL Search Params (`nuqs` или `useSearchParams`), обеспечивая шаринг ссылок и работу кнопок «Назад/Вперед».

---

## 7. Антипаттерны и частые ошибки (Pitfalls)

- ❌ **Async Client Components:** Клиентские компоненты (`'use client'`) **не могут** быть асинхронными (`async function`). Для загрузки данных на клиенте используются хуки жизненного цикла или React Query/SWR.
- ❌ **Утечка серверных зависимостей:** Запрещен импорт серверных модулей (Prisma, fs, секретные ключи окружения без префикса `NEXT_PUBLIC_`) в клиентские компоненты.
- ❌ **Сброс кэша без нужды:** Использовать `revalidatePath` и `revalidateTag` точечно в Server Actions или обработчиках вебхуков.
