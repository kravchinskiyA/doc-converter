# 2. Архитектура монорепозитория и взаимодействие (architecture-monorepo.md)

## Структура Monorepo

```text
apps/
  web/          # Next.js (App Router, FSD) — UI сайта, кабинета и админки
  api/          # NestJS + Express — бизнес-логика, авторизация, биллинг, файловый шлюз
  worker/       # TypeScript/Node.js — координаторы BullMQ и запуск конвертеров
  maintenance/  # Фоновые процессы: Outbox-диспетчер, очистка TTL, сверка очередей
packages/
  core/           # Чистая предметная логика, порты интерфейсов, расчет квот
  infrastructure/ # Реализация портов: БД (Prisma), S3, BullMQ, SES, KMS, конвертеры
  contracts/      # Общие DTO, схемы Zod, типы запросов/ответов API
```

## Единый Origin и маршрутизация
- Сайт, кабинет, админка и API обслуживаются через единый публичный HTTPS origin (обратный прокси).
- Входной прокси направляет `/api/*` напрямую в NestJS, остальные маршруты — в Next.js.
- Потоковая загрузка входных файлов и скачивание готовых результатов производятся **напрямую через NestJS** без промежуточного проксирования через Next.js и без накопления файла целиком в RAM.
- Для SSR Next.js запрашивает внутренний адрес NestJS с передачей контекста сессии. Персональные ответы и cookie не кешируются между пользователями.

## Межпакетные зависимости
- `packages/core` не зависит от фреймворков (NestJS, Next.js, Prisma, BullMQ, AWS SDK) и содержит чистые интерфейсы (порты).
- `packages/infrastructure` реализует порты из `packages/core`.
- `apps/*` импортируют логику из `packages/*`, но не импортируют код напрямую между соседними `apps/`.
